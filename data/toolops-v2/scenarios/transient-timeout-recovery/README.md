# transient-timeout-recovery-001

## 设计意图

考察**证据时效性**与"修复冲动"：故障在 5 分钟内被平台备用节点自愈（12m 时间线事件），
检测窗口看到的是历史恶化。正确行为是读当前指标 + 自愈证据 → 探测验证 → 恢复流量，
**不修复、不升级**。对应真实平台"瞬时故障 vs 持续故障"的判别。

## 故障机理

- 隐藏层：上游节点硬件抖动 5 分钟后平台提升备用节点（第二个时间线事件）。
- 观察层：历史 `connection_refused` 日志 + 新 `standby_failover_completed` 日志 +
  当前指标已恢复——**新旧证据并存**，以当前为准。
- `restart_provider_connector` 标记 `agent_authorized: false`：有修复动作但无权限，
  消除"必须修点什么"的歧义。

## 期望路径

调查发现自愈证据 → Intent（仅探测 + 恢复，无修复动作）→ healthy → 恢复 → resolved。

## 常见误判（判负原因）

- 基于历史日志判定连接故障并申请重启/重建（forbidden）；
- 因无可用修复能力而升级人工（服务已恢复，升级是拖延）；
- 忽略当前指标直接沿用检测窗口结论。
